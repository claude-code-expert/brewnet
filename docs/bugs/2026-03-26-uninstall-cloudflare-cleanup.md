# Bug Fix: `brewnet uninstall` Cloudflare Cleanup Incomplete

**Date**: 2026-03-26
**Severity**: High — leaves orphaned DNS records and Cloudflare Tunnel after uninstall
**Fixed in**: `packages/cli/src/commands/uninstall.ts`

---

## Root Cause

Two independent bugs in the Cloudflare cleanup section of `uninstall.ts`:

### Bug 1 — Builtin service DNS records not deleted

The DNS cleanup loop only iterated `state.domainConnections` (app-specific connections added via the Admin UI Domain tab). Builtin service routes created during initial setup were never included:

```typescript
// BEFORE (line 268): only app connections
const hostnames = (state.domainConnections ?? []).map((c) => c.hostname);
```

Builtin services that were missed:
| Service | Hostname example |
|---------|-----------------|
| Gitea | `git.simplite.net` |
| Nextcloud | `cloud.simplite.net` |
| FileBrowser | `files.simplite.net` |
| Jellyfin | `media.simplite.net` |
| pgAdmin | `pgadmin.simplite.net` |
| MinIO | `minio.simplite.net` |

These hostnames are generated by `getActiveServiceRoutes(state)` in `cloudflare-client.ts` and were always set up during tunnel ingress configuration, but were never cleaned up on uninstall.

Additionally, apex (`@`) domain connections created a `www.{domain}` DNS record (`wwwCnameRecordId`) that was also never included in the cleanup loop.

### Bug 2 — Quick Tunnel projects skip entire CF cleanup block

```typescript
// BEFORE: entire cleanup skipped for quick tunnel mode
if (tunnelMode === 'named' && state) {
  // cleanup code
} else if (tunnelMode === 'quick') {
  console.log('Quick Tunnel은 계정 연동이 없어 CF 측 정리가 필요 없습니다.');
}
```

If a project was initialized in Quick Tunnel mode and later upgraded to Named Tunnel mode through the Admin UI Domain Settings, the `tunnelMode` field retains `'quick'` while CF credentials (`apiToken`, `accountId`, `tunnelId`) are populated. The guard condition caused the entire cleanup block to be skipped for these projects.

**Result**: After uninstall, CF retains:
- All DNS CNAME records pointing to the tunnel (`*.cfargotunnel.com`)
- The Named Tunnel itself, showing as `DOWN` in the CF dashboard

---

## Patch Details

**File**: `packages/cli/src/commands/uninstall.ts`

### Change 1 — Condition relaxed: credentials-based instead of mode-based

```typescript
// AFTER: run cleanup whenever CF credentials are present
if (state?.domain?.cloudflare) {
  const cf = state.domain.cloudflare;
  const { apiToken, accountId, tunnelId, tunnelMode, ... } = cf;

  if (apiToken && accountId && tunnelId) {
    // automatic cleanup (both named and upgraded quick tunnel)
  } else if (tunnelMode === 'named') {
    // named tunnel but no credentials — manual guide
  } else {
    // quick tunnel with no credentials — truly nothing to clean up
  }
}
```

### Change 2 — Full hostname set built from builtin routes + app connections + apex www

```typescript
// Import getActiveServiceRoutes from cloudflare-client
const { getDnsRecords, deleteDnsRecord, getActiveServiceRoutes } = await import('../services/cloudflare-client.js');

// Builtin service hostnames (git, cloud, files, media, pgadmin, minio)
const builtinHostnames = zoneName
  ? getActiveServiceRoutes(state).map((r) => `${r.subdomain}.${zoneName}`)
  : [];

// App connection hostnames + apex www
const appHostnames: string[] = [];
for (const conn of state.domainConnections ?? []) {
  appHostnames.push(conn.hostname);
  if (conn.subdomain === '@' && conn.domain) {
    appHostnames.push(`www.${conn.domain}`);  // apex bundle
  }
}

const hostnames = [...new Set([...builtinHostnames, ...appHostnames])];
```

---

## Post-Patch Behavior

After `brewnet uninstall`:

1. **All DNS CNAME records** pointing to the project tunnel are deleted — including `git.*`, `cloud.*`, `files.*`, `media.*`, `pgadmin.*`, `minio.*`, all app subdomains, and apex/www pairs.
2. **The Cloudflare Tunnel itself** is deleted (cascade).
3. Projects initialized in Quick Tunnel mode but upgraded to Named Tunnel are now cleaned up correctly.
4. Projects still in Quick Tunnel mode with no credentials continue to show the "no cleanup needed" message.
